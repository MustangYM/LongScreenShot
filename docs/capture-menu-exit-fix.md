# 菜单截图无法退出：修复与验证

用户触发场景：其他 App 的顶部菜单或状态栏下拉菜单展开时开始截图，浮层无法退出，影响桌面操作。

## 已确认的代码风险

- 延迟 0.18 秒后才保存 CaptureCoordinator，等待期间可能重复排队启动并遗留旧浮层。
- GlobalHotKey 对不属于自己的热键返回 noErr，吞掉了应交给其他处理器的事件。
- 每个显示器分别注册同一个 Esc；浮层使用 screenSaver 层级，无可靠的失焦撤销机制。
- 激活请求发出后立即显示遮罩，没有确认焦点交接或下拉菜单是否仍在占用输入。

以上是代码审查结果，未取得原故障时的进程堆栈，因此不将所有现象归结为已经实机证实的单一死锁。

## 修改

- 先保留展开菜单的截图，再请求激活。App 激活且 CGWindowList 中没有可见 popup-menu 层窗口时才显示浮层。每 50ms 检查，两秒超时取消；迟到的激活通知不能重新打开已取消会话。
- 同步预留截图会话，延迟回调检查会话身份，阻止重复启动；再次按截图快捷键可取消当前会话。
- Esc 和 ⌘⇧Esc 按整个会话注册一次。热键回调支持 default、eventTracking 和 modalPanel run-loop 模式；不匹配的事件返回 eventNotHandledErr。
- 本地 Esc、右键可取消；⌘Q 走正常退出流程；不拦截系统的 ⌘⌥Esc 强制退出快捷键。
- 使用 popup-menu 上方的窗口层级替代 screenSaver。普通截图失焦撤销；长截图主动失焦时仍保持鼠标穿透。
- 关闭时先让所有显示器上的浮层和长截图工具栏鼠标穿透并隐藏，再取消后台任务及清理资源。关闭、取消及光标恢复均可重复调用。
- 保存、OCR、翻译前先撤掉截图浮层，避免后台操作或弹窗期间仍有全屏遮罩。

## 验证

`swift test --scratch-path /tmp/longshot-perf-debug`：30 项 Debug 测试通过。

新增 8 项覆盖：未激活时禁止显示、状态栏菜单仍跟踪时禁止显示、菜单与菜单栏区分、取消后的迟到激活、重复启动／取消、延迟启动前取消、捕获失败清理、窗口层级。

测试没有在用户桌面主动重演可能锁住输入的旧版本故障；系统菜单焦点交接和系统强制退出窗口仍需新版实机验证。菜单窗口判断依据公开的窗口层级，非所有第三方自绘菜单的完整识别器。

## 自身状态栏菜单截图补充修复

用户确认外部 App 菜单截图已正常，但本 App 的菜单展开时仍要点击桌面收起菜单后才出现截图界面。

自身菜单路径仍使用 DispatchQueue.main.asyncAfter 的 0.18 秒启动延迟，该工作会等待本 App 的菜单跟踪结束。现在由 NSMenuDelegate 记录正在展开的状态栏菜单：快捷键触发时立即采集屏幕，采集完成后通过 start(afterSnapshot:) 回调调用该菜单的 cancelTracking()，再沿用焦点／菜单窗口检查显示浮层。点击菜单里的“截图”命令仍保持原来的延迟，避免将操作菜单带入普通截图。

新增两项回归测试，验证采集先于关闭菜单，以及已经取消的延迟会话不会再关闭菜单。32 项 Debug 测试全部通过。此次未用 UI 自动化对自身菜单的完整快捷键流程进行实机复验。

## 自身菜单最终调整：使用非阻塞弹出面板

用户先后实机确认：去掉截图延迟、本地 NSEvent 菜单监听、Carbon dispatcher 直接分发，都不能解决自身 NSMenu 展开期间的快捷键无响应。以上尝试已撤回，不将它们的编译或单元测试通过视为实机修复成功。

现在状态栏按钮显示 NSPopover，原有 NSMenu 仅保存菜单项数据，不再交给 statusItem.menu 展示或运行菜单跟踪循环。原截图、长截图、历史、关闭贴图、检查更新、设置、退出命令保留，由普通 AppKit 按钮派发。面板支持点击外部关闭、重复点图标关闭、Esc 关闭。外观变为系统弹出面板。

全局热键恢复外部菜单截图已正常的实现。面板展开时按截图快捷键，先同步截取屏幕，再关闭面板，最后进入现有激活与浮层流程。点击面板中的截图按钮仍先关闭面板，避免普通截图带入面板本身。

34 项 Debug 测试通过，包括新增的命令映射、分隔线、设置快捷键及取消回调测试，以及原有截图生命周期与拼接测试。Xcode 实机日志已记录 shortcut.popover.open 后 1.35 秒出现 shortcut.popover.capture，确认面板展开时快捷键进入截图函数。最终画面保留及框选退出结果仍待用户确认。
