# 宽留白网页匹配中断修正

用户提供的两次日志中，2604×1516 和 2782×1544 选区处理约 5–7ms/帧，队列为零；第二次在 seq=90 后继续收帧但没有新拼接。用户确认内容为 Chrome 网页、正文两侧留白。日志没有逐次匹配拒绝原因，无法直接还原失败帧，但可以排除本次为处理积压。

新增非重复正文夹在宽背景和固定侧栏中的测试，旧算法均不能匹配。全幅亮度相关和固定列采样会被背景稀释，少量正文列也难以区分相似文字行。

修正使用纵向亮度梯度匹配，根据列的纵向细节与帧间变化排除留白及静止侧栏；将有限的横向搜索样本均匀分配到有效正文列，另留独立列逐行复核。原有相关性、歧义差距、逐行误差阈值和整数位移搜索保持。静止判断使用精确签名比较，避免全幅平均差异把窄正文运动当作静止。

拒绝匹配时按频率记录 visual.match.rejected：有效列数量、候选位移、相关性得分、歧义差距、逐行误差及拒绝原因，方便后续定位真实页面问题，不写入网页内容或图片。

验证：45 项 Debug 测试通过。两侧大留白网页模拟 100 次连续滚动，逐帧坐标及完整拼接结果一致；宽留白重复文字仍拒绝。4400×2400 的 120 帧回放平均 14.40ms/帧，1948×1458 平均 6.41ms/帧。真实用户网页仍需新版实机确认。
